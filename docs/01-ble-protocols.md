# 三族 BLE 协议

全部来自 `com.zdtc.ue.school` 的 `blelib` 反编译 + 实机验证。

> **证据等级约定**（重要）
> - ✅ **实测**：真机抓包确认过收发
> - 🔍 **反编译**：代码里读出来的常量/流程，未在真机复现
> - ❓ **推测**：根据现象推断，随时可能被推翻，**不要当成事实**
>
> 下面每一条都标了等级。标 ❓ 的部分不要直接写进代码去「试」。

| 协议族 | 设备 | 服务 | 写 | 通知 | 加密 |
|---|---|---|---|---|---|
| YQ | 洗衣机 | `0000fff0` | `fff2` | `fff1` | 无（明文 ASCII） |
| HNH | 烘干机 | `0000fee9` | `d44bc439-abfd-45a2-b575-925416129600` | `…9601` | DES/ECB 会话密钥 |
| XN | 热水器/直饮水 | `0000ff12` | `ff01` | `ff02` | AES-128-CBC + CRC8 |

> **服务选择坑**：HNH 设备同时暴露 `fee8` 和 `fee9`。`fee8` 是配置/OTA 通道（特征 `003784cf-…`/`013784cf-…`），真正的串口在 `fee9`。按服务遍历时若先遇到 `fee8` 就会选错通道，表现为「发了帧但设备回无关数据」。**必须先归类服务，再在 fee9 里挑特征。**

## 1. YQ（洗衣机）

- 服务 `0000fff0`，写 `0000fff2`，通知 `0000fff1`
- 明文 ASCII，无握手、无加密

| 动作 | 指令 | 回执 | 等级 |
|---|---|---|---|
| 启动 | `"X5750000" + pulse` | 实测只收到 `"X575"`（4 字节回显） | ✅ 指令、✅ 回显 |
| 启动成功回执 | — | ❓ 未抓到过，不要依赖 | ❓ |

档位 `pulse`：1 单脱水 / 2 快速洗 / 3 标准洗 / 4 大件洗 —— 🔍 来自反编译与小程序档位表，**真机未逐档验证**。

实测现象：写 `X57500001` 后收到 `X575`（4 字节回显），说明通道正确，但完整回执需要机器状态配合，属于正常中间态。

**注意**：洗衣机待机不广播（深度睡眠）。要么按机身电源键唤醒，要么用已知 MAC 直连（Android `connectGatt` 支持，iOS/macOS CoreBluetooth 不支持直连未广播设备）。

## 2. HNH（烘干机）

- 服务 `0000fee9`，写 `d44bc439-abfd-45a2-b575-925416129600`，通知 `…9601`
- 帧格式：`[3B 命令头][负载][1B XOR 校验]`，XOR 覆盖命令头 + 负载
- 加密：DES/ECB/NoPadding
- 等级：🔍 命令表来自反编译；`A70108` 握手已在真机走通（✅）

### 会话密钥派生

```
1. TX  A7 01 08 + schoolKey(8B) + XOR
2. RX  A8 01 0A + [n,o,p,q,r,s,t,u] + 尾
3. v  = [n^0x20, o^0x16, p^0x10, q^0x18, r^v0, s^v1, t^v2, u^v3]
4. fw = DES(schoolKey, v)
5. fy = DES(fw, schoolKey)        ← 会话密钥
```

`schoolKey` 全校共享（实测 `0102030405060708`），也可由 `device/findDeviceRate` 明文返回。

### 命令表

| 命令 | 方向 | 说明 |
|---|---|---|
| `A70108` | TX | 握手，负载 = schoolKey |
| `A8010A` | RX | 握手成功，负载 8B 用于派生 |
| `A80 102` | RX | 密钥错误（换 key 重试） |
| `A70A08` | TX | 取密钥 / 收单 |
| `A80A00` | RX | 收单确认 |
| `A70208` | TX | **启动**：DES([K(4B)][金额×100(2B)][p,q]) |
| `A80200` | RX | **启动确认** |
| `A70708` | TX | 结算 |
| `A70508` | TX | 结算查询 |

- `K` = 手机号后 8 位按 BCD（8 位 hex），仅作设备端记账 ID
- `p,q` = 握手负载第 2、3 字节
- 档位金额：0.8 / 1.5 / 2.5 / 2.8 元

### 实操坑

1. **一次只发一帧**：每发一次 `A70208` 会叠加一个程序，没有取消指令。
2. **闲置约 10 秒被踢**：连上后要立刻发，别等。
3. 断电后程序会续跑（设备设计如此）。

## 3. XN（热水器 / 直饮水）

- 服务 `0000ff12`，写 `0000ff01`，通知 `0000ff02`
- 帧：`[3B 命令头][AES-CBC 密文][CRC8(明文)]`
- 密钥 = 每台设备的 schoolKey（32 hex），IV = `0102030405123456`，CRC8 poly `0x8C`

命令：`140201` 握手 / `140302` 查账单 / `140403`、`140440` 开阀 / `140605` 结算 / `140912` 密钥下发 / `140022` 数据通道。

**限制**：XN 是「4G + BLE 双通道」设备，开阀需要云端订单与会话同时成立，纯 BLE 侧会被固件拒绝（F0）。计费跟随水表读数，不跟随 BLE 指令。本客户端因此**不提供 XN 开阀**。
